# ADR-0001: Модульный монолит

- **Статус:** Accepted
- **Дата:** 2026-09-27
- **Участники:** команда К.У.М.

## Контекст

Нужна архитектура, в которой можно быстро итерировать домен управленческих моделей, симуляцию и API, не усложняя ранний этап микросервисами, сетью между сервисами и распределёнными транзакциями.

## Решение

Строим **модульный монолит**:

- один деплойный юнит backend;
- внутреннее разделение на модули по bounded context (миры, модели, симуляция, identity/audit и т.д.);
- явные публичные контракты модулей; запрет прямого доступа к чужим таблицам/хранилищам;
- общие cross-cutting concerns (логирование, auth, persistence infrastructure) вынесены отдельно.

## Последствия

**Плюсы**

- Проще локальная разработка и отладка.
- Атомарные транзакции внутри процесса.
- Позже модули можно выделить в сервисы по границам контрактов.

**Минусы / риски**

- Риск «большого комка» без дисциплины модульных границ.
- Нужны code review и правила, запрещающие скрытые связности.

**Следствия для реализации**

- Структура solution отражает модули.
- Интеграционные тесты между модулями — через публичные API модулей.
