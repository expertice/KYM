# Архитектура К.У.М.

## Обзор

К.У.М. строится как **модульный монолит** с клиентом на **Unity WebGL** и **серверной симуляцией**.

```
┌─────────────────────┐
│  Unity WebGL Client │  визуализация, UI, optimistic UX
└──────────┬──────────┘
           │ HTTPS / WebSocket (планируется)
┌──────────▼──────────┐
│   API / Application │  команды, запросы, авторизация
├─────────────────────┤
│ Domain / Simulation │  модели, миры, правила симуляции
├─────────────────────┤
│ Persistence / Audit │  хранение, версии, audit log
└─────────────────────┘
```

## Ключевые решения

| Тема | ADR |
|------|-----|
| Модульный монолит | [ADR-0001](../adr/0001-modular-monolith.md) |
| Unity WebGL клиент | [ADR-0002](../adr/0002-unity-webgl-client.md) |
| Серверная симуляция | [ADR-0003](../adr/0003-server-side-simulation.md) |
| Вложенные миры | [ADR-0004](../adr/0004-nested-worlds-tree.md) |
| Optimistic concurrency и audit | [ADR-0005](../adr/0005-optimistic-concurrency-audit.md) |

## Принципы

1. Доменная логика и симуляция живут на сервере; клиент не является источником истины.
2. Модули монолита разделены по bounded context, без скрытых cross-module DB-зависимостей.
3. Миры образуют дерево; операции учитывают иерархию и изоляцию контекстов.
4. Каждое мутирующее изменение версионируется и аудируется.
5. Документация и ADR обновляются вместе с архитектурно значимыми изменениями.

## Статус реализации

Каркас кода и runtime пока не развёрнуты. Локальный запуск приложения появится после первого инфраструктурного PR.
